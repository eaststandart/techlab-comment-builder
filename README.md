# Система автоматизации комментариев

Этот репозиторий выполняет роль изолированного буферного шлюза и сервера автоматической обработки комментариев с фотографиями и видеоматериалами для дискуссий детско-юношеского инженерного клуба во Владивостоке. Проект развернут на платформе [Творческой лаборатории познавательного развития](https://eaststandart.github.io/).

### Зачем создан этот репозиторий

1. **Безопасность и разграничение прав:** Авторы имеют доступ на запись только в репозиторий `techlab-comment-builder` для редактирования своих комментариев и отправки их для публикации. Доступ к основному репозиторию сайта (`eaststandart.github.io`) для них закрыт.
2. **Изоляция данных:** Исключена ситуация, когда случайное или ошибочное изменение кода сайта может привести к потере или повреждению комментариев и медиафайлов.

### Как это работает (Краткая логика системы)

Система принимает материалы двумя способами и передает подготовленные комментарии в дискуссии платформы:

1. **Подготовка и отправка:** автор создает комментарий в веб-форме Лаборатории или готовит Markdown-манифест и вложения в Obsidian. Комплект поступает в папку `_input/` этого репозитория.
2. **Автоматическая обработка:** GitHub Actions запускает Python-модули, которые проверяют манифест и комплектность вложений, подготавливают имена файлов и оптимизируют фотографии и видео.
3. **Передача на публикацию:** готовый комплект поступает в `_output/`. Система уведомляет основной сайт, после чего его автоматизация забирает материалы и публикует комментарий в GitHub Discussions.

*Примечание: комплекты обрабатываются последовательно. Следующий комплект передается на обработку после освобождения выходного шлюза `_output/`.*

В этой части находятся сценарий GitHub Actions, управляющие Python-модули, специализированные модули обработки манифестов и медиаматериалов, а также входной и выходной буферы.

#### Назначение директорий

* **`.github/workflows/`** — сценарии GitHub Actions. Управляют запуском главного диспетчера при поступлении Markdown-манифеста в `_input/`.
* **`_actions/`** — Python-модули. Содержат логику управления очередью, предварительной проверки манифестов, анализа комплектов, переименования и сжатия медиаматериалов.
* **`_input/`** — входная папка для Markdown-манифестов и связанных с ними фотографий и видео.
* **`_output/`** — выходной шлюз для подготовленного комплекта, ожидающего передачи основному сайту.
* **`_published/`** — служебная папка с образцом манифеста и тестовыми файлами для проверки обработки.

### Назначение подсистем

* **[Сценарии автоматизации](.github/workflows/README.md)** — описание workflow `comment_builder.yml`, условий запуска, окружения и последовательности вызова диспетчера.
* **[Управляющие скрипты Python](_actions/README.md)** — описание главного диспетчера, обработчика, анализатора, предварительной обработки манифестов, переименователя и медиакомпрессоров.

## ЧАСТЬ 2: Клиентский интерфейс и публикация (`eaststandart.github.io`)

Основной сайт отвечает за интерфейс создания комментариев, прием материалов из веб-формы, получение готового комплекта из буферного репозитория и публикацию текста и медиаматериалов в GitHub Discussions.

### Два способа отправки

* **Веб-форма:** автор заполняет форму на сайте и отправляет манифест с вложениями в `_input/` репозитория конструктора комментариев.
* **Obsidian:** автор подготавливает Markdown-манифест и связанные файлы, после чего отправляет комплект в репозиторий обычным Git push.

### Передача готового комплекта

После подготовки комплекта диспетчер сохраняет его в `_output/`, фиксирует изменения в Git и отправляет событие `comment-notify` в репозиторий основного сайта. Дальнейшее получение и публикация комплекта выполняются автоматизацией `eaststandart.github.io`.

* **[Клиентские скрипты Конструктора комментариев](https://github.com/eaststandart/eaststandart.github.io/tree/main/assets/js/comment-builder/)** — JavaScript-модули веб-формы. Отвечают за авторизацию, работу с черновиками и медиаблоками, проверку данных, формирование Markdown и отправку комментария с вложениями. Подробное описание цепочки скриптов находится в [README клиентской подсистемы](https://github.com/eaststandart/eaststandart.github.io/blob/main/assets/js/comment-builder/README.md).
