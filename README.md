# Конструктор комментариев TechLab

Репозиторий выполняет роль буферного шлюза для приема, проверки и обработки комплектов комментариев с медиавложениями. Он принимает данные из веб-формы и Obsidian, подготавливает материалы и передает готовые комментарии в основной репозиторий сайта [eaststandart.github.io](https://github.com/eaststandart/eaststandart.github.io).

### Зачем создан этот репозиторий

1. **Изоляция и безопасность:** прием данных выполняется отдельно от основного репозитория сайта.
2. **Обработка материалов:** фотографии и видео проверяются и оптимизируются перед публикацией.
3. **Управление публикацией:** манифесты позволяют сохранять черновики, удалять комплекты и задавать дату публикации.
4. **Последовательная обработка:** GitHub Actions запускает единый диспетчер, который управляет очередью и не допускает одновременной передачи комплектов в `_output`.

### Как это работает

1. Автор отправляет манифест и вложения в папку `_input/` через веб-форму или Obsidian.
2. Единственный workflow `comment_builder.yml` запускает главный модуль `comment_builder.py`.
3. `comment_builder.py` синхронизирует репозиторий и проверяет, свободна ли папка `_output/`. Если там находятся файлы предыдущего комплекта, диспетчер ожидает их удаления.
4. `comment_processor.py` запускает `manifest_processor.py`. После предварительной обработки главный диспетчер отдельно фиксирует изменения `_input/` в Git и отправляет их в GitHub.
5. Затем `comment_processor.py` запускает `manifest-analyzer.py`. Анализатор проверяет дату и комплектность вложений, вызывает `comment_renamer.py` и соответствующие компрессоры, после чего переносит подготовленный комплект в `_output/`.
6. Главный диспетчер фиксирует комплект в Git, отправляет сигнал основному сайту и ожидает очистки `_output/`. Только после этого начинается обработка следующего комплекта.

Примечание: обработка выполняется последовательно. Дата публикации проверяется по времени Владивостока (UTC+10).

В этой части находятся сценарий GitHub Actions, управляющие Python-модули и специализированные модули обработки манифестов и медиаматериалов, а также входной и выходной буферы.

### Назначение компонентов

* **`.github/workflows/comment_builder.yml`** — единственный workflow. Запускает главный диспетчер при поступлении Markdown-манифеста в `_input/`, настраивает Python, зависимости и FFmpeg, запрещает параллельную работу диспетчеров.
* **`_actions/comment_builder.py`** — главный диспетчер. Управляет очередью комплектов, синхронизацией репозитория, проверкой и ожиданием освобождения `_output/`, Git-коммитами и уведомлением основного сайта.
* **`_actions/comment_processor.py`** — запускает предварительную обработку и анализатор в установленной последовательности. Возвращает диспетчеру результат работы анализатора.
* **`_actions/manifest_processor.py`** — читает только поле `published` из Front Matter. Сохраняет `true` и `false`, удаляет комплект при `delete`; некорректные манифесты также удаляются.
* **`_actions/manifest-analyzer.py`** — проверяет статус публикации, дату и наличие вложений. Вызывает переименователь и компрессоры, подготавливает комплект и переносит его в `_output/`.
* **`_actions/comment_renamer.py`** — приводит имена файлов комплекта к единому формату.
* **`_actions/media_compressor_photo.py`** — оптимизирует фотографии и сохраняет их в WebP.
* **`_actions/media_compressor_video.py`** — выполняет два варианта кодирования через FFmpeg и выбирает файл меньшего размера.

### Управление жизненным циклом манифеста

Поле `published` во Front Matter определяет дальнейшее действие:

| Значение | Действие |
|---|---|
| `false` | Черновик и его вложения сохраняются в `_input/`. |
| `true` | Манифест передается анализатору для проверки даты и комплектности. |
| `delete` | Манифест и связанные с ним вложения удаляются. |
| Другое значение или ошибка | Манифест считается некорректным и удаляется. |

### Дата публикации

Анализатор сравнивает значение `date` в формате `YYYY-MM-DD` с текущей датой по Владивостоку.

* **Будущая дата:** комплект остается в `_input/` до следующего запуска обработки.
* **Сегодняшняя или прошедшая дата:** комплект допускается к обработке.
* **Отсутствующая или некорректная дата:** комплект пропускается с сообщением в журнале.

Запуск выполняется по событию `push` манифеста. Отдельного планировщика, который автоматически запускает обработку в момент наступления даты, сейчас нет.

## ЧАСТЬ 2: Клиентский интерфейс и публикация (`eaststandart.github.io`)

Основной сайт отвечает за форму создания комментариев, отправку манифестов и вложений в буферный репозиторий, а также за публикацию готового текста и медиаматериалов в GitHub Discussions.

### Два способа отправки

* **Веб-форма:** преподаватель заполняет форму на сайте и отправляет комплект с помощью технического токена. Данные поступают в `_input/`.
* **Obsidian:** автор подготавливает Markdown-манифест и связанные файлы, после чего отправляет их в репозиторий обычным Git push.

### Передача готового комплекта

После подготовки комплекта главный диспетчер фиксирует его в Git и отправляет событие `media-notify` в основной репозиторий сайта. Сайт получает комплект из `_output/` и выполняет дальнейшую публикацию в GitHub Discussions.

## Последовательность обработки

* При поступлении манифеста запускается единственный workflow `comment_builder.yml`.
* Главный диспетчер проверяет `_output/` и при необходимости ожидает его очистки.
* Предварительная обработка выполняется до анализатора; её изменения в `_input/` сохраняются отдельным Git-коммитом.
* Черновики с `published: false` остаются в буфере без передачи на публикацию.
* Комплекты с `published: true` проверяются по дате и наличию всех вложений.
* Анализатор вызывает переименование и компрессию медиаматериалов, затем передает готовый комплект в `_output/`.
* После Git-коммита и уведомления сайта диспетчер ожидает очистки `_output/` и только затем начинает следующий цикл.

## Дальнейшее развитие

Возможные направления улучшения интерфейса и конвейера:
1. Предварительный просмотр Markdown перед отправкой.
2. Счетчики символов и остатка до ограничения.
3. Предупреждение о несохраненных изменениях формы.
4. Изменение порядка медиаблоков.
5. Индикатор хода загрузки файлов.
6. Предварительный просмотр выбранных фотографий.
